# WireGuard installer

![Lint](https://github.com/angristan/wireguard-install/workflows/Lint/badge.svg)
[![Say Thanks!](https://img.shields.io/badge/Say%20Thanks-!-1EAEDB.svg)](https://saythanks.io/to/angristan)

**This project is a bash script that aims to setup a [WireGuard](https://www.wireguard.com/) VPN on a Linux server, as easily as possible!**

WireGuard is a point-to-point VPN that can be used in different ways. Here, we mean a VPN as in: the client will forward all its traffic through an encrypted tunnel to the server.
The server will apply NAT to the client's traffic so it will appear as if the client is browsing the web with the server's IP.

The script supports both IPv4 and IPv6. Please check the [issues](https://github.com/angristan/wireguard-install/issues) for ongoing development, bugs and planned features! You might also want to check the [discussions](https://github.com/angristan/wireguard-install/discussions) for help.

WireGuard does not fit your environment? Check out [openvpn-install](https://github.com/angristan/openvpn-install).

## Usage

Clone this repository on the server and run the installer from the checkout. Answer the prompts to configure WireGuard.

```bash
./install.sh
```

It will install WireGuard (kernel module and tools) on the server, configure it, create a systemd service and a client configuration file.

Run the script again to add or remove clients!

### Check whether the service is active

On Linux with systemd, run this command from the checkout.

```bash
./status.sh
```

The script uses Python 3 to query systemd. It prints `active` and exits with code `0` when the service is running. It prints `inactive` and exits with code `1` when the service is stopped. Other exit codes indicate an unexpected state or a query error, with a diagnostic on stderr.

### Start or stop the service

```bash
./up.sh
./down.sh
```

These scripts run `sudo systemctl start` and `sudo systemctl stop` for the configured WireGuard service.

### Show the listen port

```bash
./port.sh
```

The script uses `sudo` and Python 3 to read `ListenPort` from `/etc/wireguard/<interface>.conf`. The same command works while the service is running or stopped.

### Check a UDP port

```bash
./udp.sh
./iptables.sh
```

Both scripts run without arguments and call `port.sh` to get the configured WireGuard port from disk. The returned port must be a five-digit decimal number from `10000` to `65535`.

`udp.sh` lists matching local UDP sockets using `ss`. `iptables.sh` uses `iptables -C` to check for a matching UDP `ACCEPT` rule in the `INPUT` chain. Each check passes through its underlying command's output and exit code.

### Change the listen port

Stop the configured service manually with `./down.sh`, then run `./random.sh` in a terminal. It uses Python 3 and requires the systemd unit to be loaded and inactive.

Review the interface configuration path, the old and new ports, and the diff. The changes cover `ListenPort` and matching UDP firewall hooks generated by the installer. Type the displayed new port to apply the previewed change. If the service state or configuration changes during confirmation, rerun the command to get a fresh preview. A successful change prints the path of the backup alongside the original configuration.

Use `./up.sh` when you are ready to start the service. The installer gets the endpoint port for future clients from `/etc/wireguard/params`. Existing clients use the `Endpoint` in their own configuration files. Handle those endpoints separately when using the new port.

### Select the interface

`status.sh`, `port.sh`, `up.sh`, `down.sh`, and `random.sh` use the same interface configuration. The repository default is `wg0`, stored in `config/interface`.

To use `wg1` for your account, write the interface name to your personal configuration file.

```bash
mkdir -p "$HOME/.config/wireguard-scripts"
printf '%s\n' wg1 >"$HOME/.config/wireguard-scripts/interface"
```

Use `$XDG_CONFIG_HOME` in place of `$HOME/.config` if it is set to an absolute path. A missing, unreadable, or empty personal file uses the repository default. Both files contain a single interface name.
